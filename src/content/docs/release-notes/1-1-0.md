## Summary

SiteSync 1.1.0 builds on 1.0.1 with the device lifecycle features discussed in the weekly syncs.

- **Device lifecycle.** Devices can be archived and un-archived, and a failed or replaced sensor can be swapped through a guided flow that keeps its tag path, history, and configuration.
- **Accountability.** A configurable audit log records who did what: device changes, downlinks, profile and connection edits, and sign-ins.
- **Commissioning.** Devices still being commissioned can be marked **In testing**, so they report normally but stay out of dashboards and counts until they go live.
- **Field use.** Filters persist across navigation, sites can be viewed on a map, and dashboards report device and alarm counts accurately.

## Highlights

- Archive and un-archive devices, with an **Archived Devices** page (search, filters, CSV export) in Enterprise Management and the Field App.
- Guided sensor replacement: the new sensor takes over the old sensor's tag path, so tags, history, and alarms continue. The old sensor is archived with a recorded reason, and its downlinks can be re-sent to the new one.
- Audit log with a configuration screen in Enterprise Management (choose which actions are recorded, 90-day default retention), an event viewer with CSV export, and a **Downlinks & Changes** tab on each device's Activity page.
- Commissioning (**In testing**): a toggle on the device edit page. Devices in testing keep reporting but are excluded from dashboards, health scores, and alarm counts.
- Site maps: every device with an install location shown on a map per site, with a device card and a link to its details.
- Sticky filters: device list filters and search are remembered when you open a device and come back, shown as removable filter chips.
- Device profile **Save** no longer changes untouched settings, including Fragment Payloads.
- Duplicate DevEUIs are blocked everywhere: an existing or archived DevEUI can no longer be added a second time.
- Accurate alarm counts per site and across the enterprise.

## Functional changes

### Device lists and search

- **Added** sticky filters. Device list filters and search persist for the session, including after returning from a device page. Active filters show as chips; on a phone the first few are shown with a **+N more** chip that lists the rest.
- **Added** a **Columns** button to the Enterprise device table. Each user chooses the visible columns, and the choice is saved per user.
- **Changed** device search in Enterprise Management to also match tag path, site, and sensor type.
- **Added** a **Live / In testing** filter and a **Testing** column (also in the Excel export).
- **Added** an **Archived devices** button to the Enterprise device table and the Field App device list.
- **Changed** **Clear** in the Field App so it clears every filter, including the filter panel toggles.
- **Fixed** the Field App device list showing a blank "Site:" filter chip at the start of a session; it now shows **All sites**.

### Device details and editing

- **Added** a **Downlinks & Changes** tab on the device Activity page, with **All / Downlinks / Changes** views, a time window, and CSV export. See [Downlink history](/use/downlink-history/).
- **Added** a full-screen photo viewer. Tap a device photo to view it, with a **Change photo** button.
- **Changed** tag path edits so the Ignition tag moves with the stored path. If the tag cannot be moved, nothing is changed and the device keeps receiving data. See [Move and rename tags](/use/move-rename-tags/).
- **Changed** device edit **Save** to check each step. A failed save now shows an error and stays on the page instead of returning as if it succeeded.
- **Changed** the Activity card to list all entries, not just the first ten.
- **Fixed** device history on phones. The page scrolls to the chart, and value tiles wrap long names instead of cutting them off.
- **Fixed** activity and MQTT log times shifting by the browser's time offset.

### Archive and replace sensor

- **Added** **Archive Device** under **Device Actions**. Archived devices leave device lists and dashboards but keep their history, and can be un-archived at any time.
- **Added** the **Archived Devices** page, with filters for site, replaced or archived, reason, period, and archived by. Each row offers **Open device**, **Open successor**, and **Un-archive**, plus CSV export.
- **Added** **Un-archive**. If the device's tag path was handed to a replacement, you choose a new tag path, with a suggested one offered.
- **Added** an archived banner on the device page ("Replaced by …" or "This sensor is archived"), with links to the new device and to un-archive.
- **Changed** **Replace device** into a four-step **Replace sensor** flow:
  1. Find the new sensor, optionally limited to the same type and site, or add one.
  2. Review what carries over.
  3. Give a reason (**Failed**, **Battery**, **Damaged**, **Upgrade**, **Other**).
  4. Run the swap, with each step's status and a retry.
- **Changed** replacement so the new sensor takes over the old sensor's tag path. Tags, history, and alarms continue, and name, description, metadata, install location, and photo are copied.
- **Added** **Previous device's downlinks** on a replacement device. It lists the earlier sensor's downlinks so selected commands can be re-sent to the new sensor.

See [Swap a device](/use/device-swap/).

### Commissioning (In testing)

- **Added** an **In testing (commissioning)** toggle on the device edit page. New devices start live.
- Devices in testing report normally and their own pages show live status. Dashboards, KPIs, health scores, battery and signal distributions, offline and decode-error counts, and alarm counts exclude them.
- **Added** an **In testing** badge in the device header, a banner on the device page, and a chip on Field App device cards.

### Adding devices and bulk upload

- **Changed** every add path so a DevEUI that already exists, active or archived, cannot be added again. This covers single add, the add wizard, the Field App, bulk upload, and Replace sensor. Previously a re-add could silently overwrite the existing device; now the message names the existing device and says to open or un-archive it.
- **Added** a bulk upload preview check that flags rows whose DevEUI already exists. Those rows are skipped.
- **Changed** the Field App to open the new device's page after a successful add.
- **Added** **Enter** to step through the add-device wizard. **Enter** on the last step does not save.
- **Changed** the bulk upload template to the fields SiteSync uses: `dev_eui`, `join_eui`, `app_key`, `name`, `deviceType`, `tag_path`, `description`. Serial number, location, and firmware/hardware version were removed.
- **Changed** the already-registered dialog: **Sync Again** is now **Open Device**.
- **Fixed** the Field App add form staying stuck on its loading message after an error.

### Dashboards and health

- **Fixed** alarm counts. Each site counts only the alarms of its own devices, and the enterprise total was previously inflated by the number of sites. Archived and in-testing devices are excluded.
- **Added** sensor type and location description to **Needs Attention** rows. Needs Attention search also matches site and location.
- **Added** the sensor dashboard's **Health** tab.
- **Fixed** multi-word sensor types (for example "Valve Position") opening an empty page, and the sensor page keeping the previous type's list when switching types.
- **Changed** the launch page MQTT status to show live connection state (**Connected** / **Disconnected** / "n of m connected").
- **Changed** the Site Health layout so the health score is a KPI tile and tiles wrap on narrow screens.

### Site maps

- **Added** a site map in Enterprise Management and the Field App. Each device with an install location is a pin colored by status. The map has a searchable device list, **Show all**, **Show my location**, and a device card with a link to its details.
- **Added** **View Map** buttons on site cards.

See [Site map](/use/site-map/).

### Audit log

**Added** the SiteSync audit log. It records the user, target, and a readable before/after for:

- device changes: add, bulk upload, edit, rename, tag path, move, photo, replace, archive, delete, export
- downlinks
- device profile, decoder, and UDT changes
- connection and MQTT changes
- site and RBAC changes
- sign-in/out and session start/end

**Added** **Settings › Audit Log**, with an on/off switch, a choice of which actions are recorded, profile status, **Verify profile** and **Send test event**, and an event viewer with search and CSV export. Retention defaults to 90 days.

See [Audit logging](/configure/audit-logging/overview/) and [Auditable actions](/configure/audit-logging/auditable-actions/).

### Device profiles

- **Fixed** profile **Save** changing fields the user had not changed, including Fragment Payloads, fragmented ports, and reassembler. Save waits until the profile has loaded and writes only changed fields.
- **Fixed** display values pointing every device of a profile at one device's tags, which caused duplicate or inconsistent display values.
- **Fixed** setting a profile's primary value, which was not being saved.
- **Fixed** saving profiles whose UDT inherits from another type.
- **Fixed** the value pickers on a profile with no UDT; they now explain that a UDT must be assigned first. See [Assign a UDT](/configure/device-profiles/assign-udt/).
- **Added** "Valve Position" as a sensor type.
- **Changed** the Actility device profile search panel to a cleaner layout with a close button.

### Connections

- **Fixed** MQTT topics being saved against the wrong connection, and a failed MQTT start showing a success message.
- **Fixed** connection rename reporting success when it had failed.

### Navigation and interface

- **Fixed** the blank white panel that appeared on the left behind popups and loading messages.
- **Fixed** the navigation panel switching between full and compact layouts while a page loads.
- **Fixed** clipped button shadows on the **Device Actions** card.

## Behavior changes to note

| Area | What changes |
| --- | --- |
| Field App sign-in | The Field App now requires sign-in. |
| Alarm totals | Enterprise alarm totals will be lower than before, because the old total was multiplied by the number of sites. |
| In testing devices | Devices in testing do not appear in dashboard counts or alarm counts. |
| Archived devices | An archived device stays on the network server and keeps receiving data. Delete it to stop that. |
| Log times | Activity and log times may move by the time-zone offset, because they are now read correctly as UTC. |

## Requirements

- **SiteSync module.** Install the SiteSync module release that accompanies 1.1.0 before importing the projects. Archive, Replace sensor, downlink history, and the audit log depend on it; the projects degrade gracefully on an older module, except Replace sensor.
- **Columns.** The `User_Preferences` database connection is needed to save each user's column choices.
- **Site maps.** The site map loads map tiles from `tile.openstreetmap.org`, so users' browsers need access to it. See [Ports and network requirements](/reference/ports-network-requirements/).
- **Gateway tags.** Configuration tags for commissioning, the audit log, and customizations are created automatically under `[default]SiteSync/`.

:::caution[Replace sensor needs the new module]
Every other 1.1.0 feature degrades gracefully on an older module, but **Replace sensor** does not. Upgrade the module first.
:::

## Known limitations

- Gateways are not yet shown on the site map.
- The **Alarms** tab on the sensor dashboard lists all active alarms, including those of archived and in-testing devices; dashboard alarm counts exclude them.
